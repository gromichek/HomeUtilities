# UI review 2026-11-05 — findings

Input for one batch task (owner decision 2026-11-02: findings are collected and handed over together).
Reviewed: the owner's screenshots of Overview, Bills, Bill editor, Reading dialog, Meter editor, Choice dialog,
Charges, Sync settings and Reports — phone (Android 16) portrait and landscape and Windows full / half screen, light
theme, Russian UI — plus the XAML / ViewModel code of `main` at 2f74259 for everything the screenshots did not show
(Readings, Payments, dark theme colours, loading and empty states, touch sizes).
Proposed rule changes are in `docs/UI_GUIDELINES_1.md`.

**Severity:** **Bug** — hinders use or shows wrong information · **Flaw** — inconvenient or untidy · **Wish** — improvement.
Russian UI texts are quoted as they appear (with an English gloss where needed). Amounts and dates in the examples are invented; the screenshots are not in the repository.

## Top 5

1. **R-01** Toolbar icons (✓ Save, ?, ☰, ←) nearly invisible on the dark toolbar on Android (1.6 : 1).
2. **R-06 + R-04** Choices go through `DisplayActionSheet` (~25 places): no current-value mark, and the picked record is
   found by its display text — two records with the same name → the wrong one is taken silently.
3. **R-02** Month names in English ("November 2026") on Windows in the Russian UI (6 places).
4. **R-35 + R-36 + R-37** Charges: "0,00 €" for a contract that could not be calculated, unlabeled numbers (labels exist
   in the ViewModel but are not bound), and a misleading "no price on 15.03.2023" message whose real cause is missing
   readings.
5. **R-29 + R-05** Phone: dialogs without a top bar and with Save inside the scroll area (hidden by the keyboard); all
   buttons 40 dp instead of 48.

## A. All screens

**R-01 · Toolbar (Android, light theme) · Bug**
☰ and ← are black, "?" and ✓ are the accent blue on the dark toolbar: contrast 1.9 : 1 and 1.6 : 1; ✓ is the primary
action of every editor and looks like "?".
*Fix:* set `Shell.BackgroundColor` / `ForegroundColor` / `TitleColor` in `AppShell.xaml` for both themes; add toolbar
variants of the icon sources with the `OnPrimary` colour. *Code:* `Icons.xaml` `IconHelpSource` / `IconSaveSource`
use `PrimaryLight` (#2F5D8A); no Shell colours are set anywhere.

**R-02 · Bill editor, Charges, Bill template, Import override, Report period dialog (Windows) · Bug**
Month shown as "November 2026" / "October 2026" in the Russian UI.
*Fix:* show the ViewModel's localized text (already built in `BillEditViewModel:472`, `ChargesViewModel:174`) in a
label/button; open the `DatePicker` on tap. *Code:* `DatePicker Format="MMMM yyyy"` in `BillEditView`, `ChargesPage`,
`BillTemplateEditView` ×2, `ImportRowOverrideEditorView` ×2, `ReportPeriodDialogView` ×2 — WinUI uses the Windows
language, not `CultureInfo`.

**R-03 · Forms and filters (both platforms) · Flaw**
Two looks for "pick one": a bordered box (`ReportFilterField`: Category, Supplier, filters) and the native `Picker`
(underlined like a text field: "Вид счёта", "Ресурс", "Единица"; on Reports "Группировать по / Показывать / Строки"
next to bordered ones in the same card, with a different height on Windows). ~45 native pickers in 21 files.
*Fix:* one `ChoiceField` control (today's `ReportFilterField`) + the existing `SingleChoiceDialogView` everywhere.
`ReportFilterField` also cuts the value to one line (`TailTruncation`) — allow 2 lines.

**R-04 · Choice dialogs (supplier, contract, category, property, period, template…) · Flaw**
Native action sheet: the current value is not marked, the items are grey and look disabled, lists have 8+ items
(§3a allows the native control only for 2–5).
*Fix:* route `IDialogService.ChooseAsync` to `SingleChoiceDialogView` with the current value preselected; keep the
action sheet only for commands (Camera / Gallery). *Code:* `DialogService.ChooseAsync` → `DisplayActionSheetAsync`,
~25 call sites.

**R-05 · All screens (Android) · Flaw**
Tap targets below 48 dp: every button has `MinimumHeightRequest=40`, `IconButton` is 40 × 40 (row delete icons,
‹ ›, ×, ＋ in section headers, the photo button on Readings, the ✓ "paid" on Overview).
*Fix:* `OnPlatform` Android 48 in `Styles.xaml`; keep the glyph size.

**R-06 · Choices of records · Bug (risk of wrong data)**
The chosen record is looked up by its display text, e.g.
`contracts.FirstOrDefault(c => c.Title == picked)` (`PaymentEditViewModel:510`; same pattern in bill, template,
contract and tariff editors). Two contracts with the same title in one property (old and new "Газ") → the first one
is taken without any warning.
*Fix:* choice dialogs return the Id / index (together with R-04).

**R-07 · Forms (Android) · Flaw**
Field text and the underline start ~5 dp right of the label; text buttons ("Показать начисления", "Ввести счёт",
"Открыть тариф") are indented by their padding (~8 dp).
*Fix:* bordered field look with the text aligned to the label (handler); `TextButton` horizontal padding 0.

**R-08 · Switches · Flaw**
Left of the label in editors, right of the label on Sync, Reports and in the meter's contract list. "On" colour is the
system bright blue, not the app accent.
*Fix:* form → switch left; settings row → switch right; `OnColor = Primary` in a style.

**R-09 · Month / year switcher (Bills filter, Charges, Bill editor) · Flaw**
‹ and › sit at the card edges (≈870 px apart on Windows), far from the value; they are text characters, not icons.
*Fix:* centred `Auto,Auto,Auto` group with `IconPrevious` / `IconNext`, 48 dp each.

**R-10 · Totals lines (Bills filter, Charges) at 360 dp · Flaw**
"…· Итого / 49,22 €" and "Оплачено 12,34 € · / Осталось 0,00 €" — label and amount on different lines.
*Fix:* non-breaking spaces between label and amount and before "€", or label-over-value columns as in the bill's
"Оплачено / Осталось оплатить".

**R-11 · Month abbreviations · Flaw**
Overview "окт.–3 нояб."; chart axis "Февр 26", "Март 26", "Июнь 26", "Сент 26" — different lengths.
*Fix:* own 3-letter names in resx. *Code:* `ReportLabels.cs:64` `ToString("MMM").TrimEnd('.')`.

**R-12 · Delete icons · Flaw**
Red in meter registers, blue in the bill's payment rows and in the payment editor; the reading dialog uses an outlined
button. *Code:* `IconButton` instead of `DestructiveIconButton` in `BillEditView` (payment row) and `PaymentEditView`;
`SecondaryButton` in `ReadingEditorView`.

**R-13 · Action buttons on phone · Flaw**
"Добавить платёж" (bill editor) and "Заменить счётчик…" (meter editor) have natural width, against T-028i.
*Fix:* `HorizontalOptions=Fill` on compact width.

**R-14 · Reading dialog, phone portrait · Bug**
The second photo button shows "Выбрать" — the text "Выбрать изображение…" (`PhotoChooseFile`) is cut to fit half the
width. On Windows the single button stands right-aligned at half width.
*Fix:* stack "Сделать фото" and "Выбрать изображение…" full width in an `AdaptiveFieldGrid`; on Windows one full-width
(or left-aligned) button.

**R-15 · Bills list, statuses · Flaw**
"Не оплачен" is muted grey (by design, `BillsPage.xaml` comment "grey unpaid") — the state that needs action is the
least visible. The green category dot of "Газ" equals the green of "Оплачен ✓".
`BadgeDueSoonLabel` exists but the list does not use it.
*Fix:* unpaid in normal text colour, due soon amber, overdue red; status always text + icon; default category palette
without the status green/red.

**R-16 · Navigation affordance · Flaw**
Overview to-do rows open a page but have no chevron (money rows have one); the meter's "История" row uses
`IconOpenLink` (external web page) for in-app navigation.
*Fix:* `IconChevron` for every row that opens a page; `IconOpenLink` only for web links.

**R-17 · "Mark as paid" icon (Windows) · Flaw**
Overview shows a plain check mark, the bills list a circled check. Cause: text icons use Segoe (`E73E`, also used for
Save), image icons the bundled Material font (`task_alt`).
*Fix:* Material Icons on both platforms (`UI_GUIDELINES_1.md` §1).

**R-50 · Bills, Payments filter (phone) · Wish**

## G. Charges

**R-35 · Contract cards · Bug**
A contract that could not be calculated shows "0,00 €" as its total, like a real zero. *Code:*
`ChargeCardBuilder`: `hasAmounts = Complete or Incomplete`.
*Fix:* for `Incomplete` show "—" (or "≈ total of the calculated part" with the ≈ mark).

**R-36 · Expanded card · Flaw**
Numbers without labels: "0,00 € 0,00 € 0,00 €"; on Windows the same VAT information three times
("10,00 € 21 % 2,10 €", "10,00 € 2,10 € 12,10 €", "НДС 21 % от 10,00 € = 2,10 €"); lines without amounts give no reason.
*Code:* `ChargeCardBuilder` fills `NetLabel` / `VatLabel` / `TotalLabel` ("Без НДС", "НДС", "Итого") but
`ChargesPage.xaml` does not bind them.
*Fix:* bind the labels; one line per service: "Ежемесячная плата — 12,10 € (без НДС 10,00 + НДС 21 % 2,10)" or
"Водоснабжение — нет цены".

**R-37 · Warning texts · Flaw**
"На 15.03.2023 нет действующей цены для «Водоснабжение» — добавьте цену в тарифе." in the card for October 2026.
Cause: `ChargeCalculator` looks up the price at the date of the **last reading** (`metered.RateDate`); the meter has
only its initial reading from 2023. The real problem (no readings for the month) is not named. "для «Водоснабжение»"
is ungrammatical; "Открыть тариф" appears twice for the same tariff.
*Fix:* a separate warning "Нет показаний за октябрь 2026 — последнее 15.03.2023" with a link to Readings; price text
"В тарифе нет цены для услуги «{1}» на {0}."; one "Открыть тариф" per tariff.

**R-38 · Card header · Flaw**
Status "Полностью" (fully) is unclear and indented differently from "⚠ Неполно"; the colour dot is centred on the
card, in Bills it is aligned to the first line; the action is "Ввести счёт" here and "Новый счёт" in Bills.
*Fix:* "✓ Рассчитано" with the icon in the same column as ⚠; dot aligned to the first line; one action name.
